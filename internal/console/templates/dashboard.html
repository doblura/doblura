What this is

Doblura runs Odoo the way delivery actually happens: a copy per pull request, a rehearsal of a version change against anonymised production data, a staging that persists, and production itself — all described the same way, with the same rules enforced by Kubernetes rather than by a checklist.

It holds no permissions of its own. Every action here is performed as you, so what you can do is what your access already allows, and nothing more.

Start with a customer

A customer is the record everything else hangs off: which Odoo version they run, where their environments are published, what their data holds. With one in place, an environment needs almost nothing said about it.

kubectl apply -f - <<'YAML'
apiVersion: doblura.dev/v1alpha1
kind: OdooTenant
metadata:
  name: acme
  namespace: {{if .Scope}}{{.Scope}}{{else}}your-namespace{{end}}
spec:
  displayName: Acme Industries
  default: true                 # so environments need not name it
  domain: acme.example.com      # addresses are generated under this
  images:
    - name: v18
      image: odoo:18.0
      odooVersion: "18.0"
      default: true
  environmentDefaults:
    database: {host: postgres, user: odoo, passwordSecret: odoo-db}
    storage: {filestore: {mode: Database}}
    size: small
